# Synopsis — Audio Sync, TX-500 MP, Channel Exports, WebSDR JS8Call, G-90 Clicking, AmRRON Fldigi/Flmsg (2026-09-15 to 2026-09-18)

## Situation

Multi-radio support (see the 2026-09-07 synopsis) was in place, but real
daily use over the following days exposed a run of gaps: per-radio audio
settings had to be re-entered by hand in VARA/FLRIG after switching radios,
the TX-500 MP kept dropping out of its digital mode, the IC-705 got stuck
in transmit once, and the setup script still assumed the user had hand-made
a `config.sh` before running it. On top of that the user wanted new
capabilities: TX-500 MP memory-channel programming, an offline phone
channel viewer, and receive-only JS8Call/CommStat from a web SDR with no
radio attached.

The user's stated goal throughout: each radio has its own completely
accurate configuration applied automatically at **Select Radio** time, and
the whole thing is reproducible from the repo. Personal items (callsign,
Winlink password, grid) are entered once by the user, never committed.

## What was built or fixed

- **Audio sync at select time.** `select-radio.sh` now runs
  `sync-radio-audio.sh` itself the moment a radio is chosen. Before, only
  some launchers remembered to call it, and the setup script's templates
  for Pat/Pat FM had drifted from the deployed copies. Fixed both.
- **First-run configuration prompt.** `Setup_Ham_Radio_Stack.sh` no longer
  fails when `config.sh` is missing; it asks for callsign, grid, Winlink
  password and VARA registration and writes `config.sh` itself.
- **Stable audio device IDs.** The TX-500 MP and FT-891 profiles used raw
  ALSA card numbers (`hw:1,0`). After a reconnect shifted the card number,
  the mixer script silently tuned the wrong device and left the real
  capture gain maxed. Both now use the card's real ID (`hw:Device,0`). The
  TX-500 MP mic capture was retuned (31% to 54%) against a live VARA HF
  meter (target about -24 dB).
- **TX-500 MP moved to the native Lab599 protocol.** flrig kept forcing
  the radio from DIG to USB. Root cause was a wrong flrig rig name plus
  the generic Kenwood TS-2000 emulation; the fix was the radio's own CAT
  protocol menu set to Lab599, flrig's native `TX500` driver, and Hamlib
  model 2050 for rigctld. Start_Flrig_Radio.sh now forces several flrig
  prefs on every launch because flrig reverts them on exit.
- **TX-500 MP channel export, two paths.** `channel-tools/` gained a CSV
  export for Lab599's TRX Remote Android app and a reverse-engineered
  binary `.mem` export for the TRX Mem desktop software (run under Wine).
  Both were verified against real hardware.
- **Offline read-only phone channel viewer.** An Android app that scrolls
  the channel lists on a phone with no network. A public 3-radio version
  lives in the separate Channel Picker repository; a personal version is
  kept out of both public repositories.
- **Receive-only JS8Call via a web SDR**, with **Activate / Deactivate**
  Desktop shortcuts. A virtual PulseAudio/PipeWire sink feeds a browser
  tab's audio to a separate JS8Call profile (`-r WebSDR`, `Rig=None`, own
  TCP port 2443) that can never touch the real radio setup.
- **A separate CommStat copy for the WebSDR JS8Call.** CommStat's JS8
  API allows one client per JS8Call and its Auto / RF Ack settings are
  global, so the same Activate / Deactivate shortcuts now also start and
  stop a fully separate copy in `~/CommStat-WebSDR` (own database, single
  connector, RF Ack off, opposite map theme).
- **AmRRON Fldigi + Flmsg, radio and receive-only.** Fldigi now follows Select
  Radio (audio via `PULSE_SOURCE`/`PULSE_SINK`), gets AmRRON's recommended
  settings from their setup video (Contestia 4/250 at 900 Hz, Rx ID on, AFC
  and sweet spot off, NBEMS/flmsg on, 3.588/7.110/14.110 MHz net
  frequencies), and AmRRON's custom Flmsg forms (bundled in `amrron-forms/`,
  installed into each Flmsg's `CUSTOM` folder). A separate receive-only
  Fldigi + Flmsg pair (Activate/Deactivate Fldigi WebSDR) runs from a WebSDR
  with no rig control, its own ports and forms folder. The form round trip
  is not yet tested over the air.
- **G-90 clicking fixed.** The Conky widget polled the radio every 2
  seconds with the `rigctl` client, which probes VFO A/B/A on every start.
  The Xiegu G-90 clicked audibly and flipped between VFOs. Conky's two
  helper scripts now talk to rigctld's raw text port.

## Real bugs and lessons

- **Verbose logs beat theory.** The G-90 clicking looked like a JS8Call
  problem (closing JS8Call stopped it, and a split-mode change did
  nothing). Restarting rigctld with `-vvvv` and reading the `icom_set_vfo`
  lines, then noticing short-lived `rigctl` processes, found the real
  cause in minutes. The 2026-09-07 write-up had already predicted that
  live CAT polling from Conky could cause this; it now has.
- **A misdiagnosed IC-705 stuck-transmit.** Several theories (VOX, CAT
  PTT, VARA's own PTT setting) were wrong. The actual cause was a bad USB
  cable, confirmed when a replacement fixed it. VARA HF also has no CAT
  PTT dropdown by design, unlike VARA FM; that isn't a bug.
- **Don't test on top of a live session.** While verifying the CommStat
  copy, a duplicate JS8Call and audio sink briefly disturbed the user's
  running WebSDR session, and the first version of the copy quietly shared
  a connection with the real CommStat. Both were caught and corrected; the
  lesson is to check for running sessions before starting test components
  and to verify isolation from the socket and file level, not by
  assumption.
- **Commercial channel data stays out of the public repo.** Purchased
  frequency data must never reach the public Channel Picker repository;
  the public data derives only from public sources. The READMEs link to
  the vendor's own page for users to get their own lists.

## Final status

Everything above was confirmed live by the user on real hardware: audio
sync and profile switching, TX-500 MP on Lab599 (flrig, rigctld, JS8Call
with CommStat, Pat Winlink), both TX-500 MP channel exports, the phone
viewer, the WebSDR JS8Call with its CommStat copy (Activate and Deactivate
both), the G-90 with JS8Call and Conky running together, and the AmRRON
Fldigi/Flmsg setup (radio and WebSDR versions, with the AmRRON forms in both
Flmsg copies), apart from an actual over-the-air form exchange, which the user
could not test yet. The setup
script regenerates all the WebSDR scripts and installs `rsync`, which the
CommStat copy needs.
