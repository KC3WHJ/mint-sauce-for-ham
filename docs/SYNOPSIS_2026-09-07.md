# Synopsis — Multi-Radio Support (2026-09-07)

## Situation

The station had been running with the Icom IC-705 as its only supported
radio, with per-app scripts (`Start_Pat.sh`, `Start_Flrig_Radio.sh`, etc.)
hardcoded to that one radio's serial device. The user also owns a Yaesu
FT-891, a Lab599 TX-500 MP, and a Xiegu G-90, and wanted all four properly
supported — with an explicit picker instead of auto-detection, since
having more than one radio plugged in at once had already broken the
auto-detection logic earlier in the project.

## Approach

The user pointed to [EmComm Tools OS](https://community.emcommtools.com)
(a separate Ubuntu-based ham radio distro they already use successfully
with these same radios) as a reference, specifically endorsing its
`et-radio` (explicit radio picker) and `et-mode` (explicit workflow
picker) UX patterns for reuse. Two releases of that distro were fetched
and its `radios.d/*.json` configs and `wrapper-rigctld.sh` examined for
validated per-radio settings (Hamlib model ID, baud rate, PTT type, radio
menu settings, and ALSA mixer levels). Rather than adopting EmComm's
JSON+jq format outright, the existing project convention (plain bash
`KEY="value"` profiles) was kept and extended with the same underlying
ideas.

Before any of this work began, a full system backup was taken to the
external drive per the user's request.

## What was built

- **`~/.local/bin/select-radio.sh`**: a dialog-based picker that
  symlinks `~/radio_profiles/active-radio.conf` to whichever radio you
  choose, printing that radio's operator notes (panel settings to check)
  at selection time.
- **Four launcher scripts refactored** to read that one symlink instead
  of guessing from what's plugged in: `Start_Flrig_Radio.sh` (also
  pre-selects the radio in flrig's own prefs and triggers the audio
  sync), `sync-radio-audio.sh` (updates WSJT-X/JS8Call/VARA HF/FM device
  names, plus a new `AUDIO_SCRIPT` hook for one-time ALSA mixer tuning),
  `Start_Pat.sh`, and `Start_Pat_FM.sh` (previously hardcoded to the
  IC-705 — this was a real gap found and fixed mid-session, since without
  it, picking a different radio in `select-radio.sh` wouldn't have
  actually changed what Pat Winlink talked to).
- **Four real, live-tested radio profiles**: IC-705 (already working),
  and newly built/validated profiles for the FT-891, TX-500 MP, and G-90.
  Each was confirmed against real hardware — CAT communication, correct
  audio device routing, and (for the FT-891 and TX-500 MP) ALSA mixer
  levels tuned against a live VARA HF input meter.
- **A new `AUDIO_SCRIPT` mechanism** (`radio_profiles/audio/*.sh`) for
  radios whose default USB codec levels are wrong out of the box —
  modeled on EmComm's own per-radio audio scripts, but with corrected
  control names verified against each codec's actual `amixer` output
  rather than copied blindly from the reference.
- **The `mint-sauce-for-ham` GitHub repository updated** to match: the
  new `bin/` scripts and `radio_profiles/` (four real profiles plus
  their audio scripts) were added, `Setup_Ham_Radio_Stack.sh` now
  generates the active-radio.conf-based launchers on a fresh install
  instead of the old IC-705-only versions, and the README documents the
  profile format plus two hard-won debugging lessons (below).
- **This documentation folder reviewed**: the two 2026-09-05 rebuild
  documents in it had the real callsign/grid square in plain text,
  conflicting with this project's practice of keeping personal info out
  of anything meant to be published — both were replaced with redacted
  versions (`N0CALL`/`AA00aa`, matching `config.sh.example`'s existing
  convention) and the originals moved to trash.

## Two real bugs found and fixed

- **flrig's Xiegu-G90 driver hardcodes the wrong CI-V polling address**
  (`0x88` instead of the G-90's real `0x70`) for S-meter/attenuator
  commands — a known issue from earlier G-90 debugging, re-confirmed and
  documented in `radio_profiles/g90.conf` rather than re-patched. Only
  VarAC (the one app here that needs flrig instead of `rigctld`) is at
  risk; WSJT-X/JS8Call/Pat all use `rigctld` directly and are unaffected
  — proven working live with a real VARA HF connection attempt.
- **A serious, hours-consuming diagnostic red herring on the TX-500 MP**:
  CAT communication was completely silent no matter the baud rate, RTS/
  DTR state, or radio menu setting — even after the user confirmed the
  radio's own CAT protocol menu was correct and confirmed the exact same
  radio/cable/interface combination works on another machine. The actual
  cause: the diagnostic script itself was asserting RTS (which keys this
  radio's PTT) at the same moment it tried to read the CAT reply,
  corrupting the response with its own transmit noise. Once the test
  stopped touching RTS/DTR, CAT worked immediately and cleanly. This is
  now documented as a general lesson for any RTS-keyed radio.

## Final status

All four profiles are real and tested: IC-705 (flrig/VarAC and
rigctld/WSJT-X/JS8Call/Pat, both paths), TX-500 MP (fully working, CAT +
tuned audio + Pat/VARA HF), FT-891 (fully working, CAT + tuned audio +
WSJT-X + JS8Call + Pat/VARA HF, with a caught wrong-device-path mistake
corrected once the actual hardware was tested), and G-90 (rigctld path
proven working; VarAC path documented as at-risk from the known flrig
bug, not attempted). The IC-7300 and (tr)uSDX are intentionally left as
placeholders — the user doesn't plan to use the (tr)uSDX with this
station (it's used exclusively with EmComm Tools OS, RadioMail, and a
DigiRig Lite on another machine), and the IC-7300 can wait. A second full
system backup was taken after all of this work, and the repository was
pushed reflecting the finished state.
